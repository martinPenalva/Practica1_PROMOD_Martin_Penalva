1. Introducción
En esta práctica se trabajará con una simulación realista de una planta industrial desarrollada
en Python utilizando MuJoCo, OpenCV y NumPy. El código inicial implementa una planta
formada por varias cintas transportadoras, cámaras de inspección, objetos, un horno y una isla
robotizada con un manipulador Franka Emika Panda.
El código proporcionado funciona, pero ha sido desarrollado principalmente mediante progra
mación procedural, utilizando funciones, variables globales y estructuras de datos compartidas.
El objetivo de esta práctica es refactorizar dicho código utilizando Programación Orien
tada a Objetos (POO), de forma que cada elemento de la planta quede representado mediante
una clase con responsabilidades claramente definidas.
Figura 1: Ejemplo de la planta industrial.
Esta práctica tiene además un objetivo adicional: preparar la arquitectura de software
que se utilizará posteriormente en la Práctica II. Por tanto, no se busca únicamente que el
programa continúe funcionando, sino que su estructura sea modular, mantenible y extensible.

4.6. Clase Horno
El horno deberá encapsular el comportamiento asociado a la parte final de la línea y deberá
incluir, además del registro de piezas, una variable de temperatura.
Como mínimo deberá almacenar:
Número de piezas recibidas.
Detección de entrada de una nueva pieza.
Estado del horno.
Temperatura actual del horno.
Temperatura mínima y máxima de funcionamiento.
Identificador del elemento gráfico del horno dentro del modelo MuJoCo.
La temperatura deberá poder modificarse mediante métodos de la clase. Por ejemplo:
class Horno:
def __init__(self, geom_id, temperatura_inicial=20.0):
self.numero_piezas = 0
self.temperatura = temperatura_inicial
self.geom_id = geom_id
def registrar_pieza(self):
self.numero_piezas += 1
def aumentar_temperatura(self, incremento):
self.temperatura += incremento
def disminuir_temperatura(self, decremento):
self.temperatura-= decremento
def obtener_temperatura(self):
return self.temperatura
6
Representación visual de la temperatura en MuJoCo
La temperatura del horno deberá reflejarse visualmente en la simulación modificando su color
mediante MuJoCo.
Por ejemplo, una posible codificación visual es:
Temperatura baja: azul.
Temperatura media: amarillo o naranja.
Temperatura alta: rojo.
El alumnado deberá implementar un método que actualice el color del horno en función de la
temperatura.
Una posible implementación orientativa sería:
def actualizar_color(self, model):
if self.temperatura < 50.0:
color = [0.1, 0.3, 1.0, 1.0]
elif self.temperatura < 100.0:
color = [1.0, 0.6, 0.1, 1.0]
else:
color = [1.0, 0.1, 0.1, 1.0]
model.geom_rgba[self.geom_id] = color
El método deberá ejecutarse durante la actualización de la simulación para que el cambio de
color pueda observarse directamente en la ventana de MuJoCo.
Por ejemplo:
horno.aumentar_temperatura(1.0)
horno.actualizar_color(model)
No es obligatorio utilizar exactamente estos valores de temperatura ni estos colores. El grupo
puede definir otros intervalos siempre que exista una relación coherente entre la temperatura y la
representación visual.
La clase deberá mantener encapsulada la lógica asociada al horno, evitando que la temperatura
y el color se gestionen mediante variables globales.

7. Restricciones de diseño
Se deberán respetar las siguientes condiciones:
1. No se aceptará una solución en la que simplemente se introduzca todo el código existente
dentro de una única clase.
2. Cada clase deberá tener una responsabilidad clara.
3. Se deberá reducir al mínimo razonable el uso de variables globales.
9
4. Las cintas deberán controlarse mediante objetos.
5. Las cámaras deberán ser objetos independientes.
6. La detección visual deberá realizarse dentro de la clase de cámara o mediante una clase
específica de visión utilizada por esta.
7. La cámara deberá determinar la forma de las piezas.
8. La detección de una pieza deberá activar una variable booleana.
9. Dicha variable deberá permitir detener la cinta correspondiente.
10. La aplicación deberá continuar ejecutándose en MuJoCo.
11. Se deberá mantener la visualización de las cámaras mediante OpenCV.
12. El horno deberá gestionar su temperatura mediante atributos y métodos propios.
13. El color del horno deberá cambiar en MuJoCo en función de su temperatura.
14. La cinemática inversa del robot no deberá ser reimplementada.
8. Estructura orientativa del proyecto
Una posible estructura de archivos sería:
planta_industrial/
|
+-- main.py
+-- requirements.txt
|
+-- src/
|
+-- __init__.py
+-- planta.py
+-- cinta_transportadora.py
+-- camara_inspeccion.py
+-- objeto_industrial.py
+-- horno.py
+-- robot.py
En esta organización, main.py debe permanecer en la raíz del proyecto y actuar únicamente
como punto de entrada de la aplicación. Las clases y módulos que implementan la lógica de la
planta deberán ubicarse dentro del directorio src/.
Por ejemplo, desde main.py se podrán importar las clases mediante:
from src.planta import PlantaIndustrial
def main():
planta = PlantaIndustrial()
planta.ejecutar()
if __name__ == "__main__":
main()
No es obligatorio utilizar exactamente estos nombres de archivo, pero sí se deberá mantener
una organización equivalente: el programa principal separado de las clases y la lógica de negocio.
